## Release-blocking findings

1. **Web/security integration is missing.** The current base has the wine design system, redesigned web routes, expanded descriptor search, image transformation/dimension tracking and rebuilt generation prompts. PR3 still contains the older web route layouts plus security/payment changes. Choosing all of either side would discard authorized work. Resolve presentation separately from account-action guards, creator-local booking snapshots, payment reconciliation, atomic generation holds and service-side permissions; run web journeys against the resolved tree.
2. **New web uploads need the current authorization and media architecture.** Current-base [`upload-image`](https://github.com/Abbsogol/the-palette/blob/1bc0a544262da2865a8df89fa549b04df801a9d9/app/api/upload-image/route.js#L21) places chat photos in `designs`, returns a public URL, and authorizes administrative purposes using `profiles_data.is_admin` (lines 36–38). The beta dashboard instead requires active service-controlled staff membership, verified identity and authenticator MFA, and private chat attachments use `mobile-uploads`. Do not introduce this new route unchanged, or solve its failing session-inventory test by exempting it.
3. **New public service-role statistics bypass member/profile visibility.** Current-base [`creator-reply-time`](https://github.com/Abbsogol/the-palette/blob/1bc0a544262da2865a8df89fa549b04df801a9d9/app/api/creator-reply-time/route.js#L8) accepts an arbitrary creator ID without a session or profile-visibility check, reads conversation/message metadata with the service role, and sets shared-cache headers. It exposes only aggregates, not message bodies, but remains outside the members-only contract. Bind it to authenticated, permitted profile access; cache only after accounting for visibility, blocking, suspension and deletion.
4. **Onboarding/profile reconciliation must preserve both sets of constraints.** Current web onboarding still assigns a three-credit starting balance through a direct profile update; beta uses atomic `complete_onboarding` with age/privacy confirmation and the new entitlement rules. The redesigned web profile separately persists private health/booking notes in RLS tables. Those tables are present in the baseline, so preserve their segregation without reverting username/media validation, subscriptions, account lifecycle or atomic onboarding.
5. **Policy release must be reconciled with shipped behavior.** `app/privacy/privacy.module.css` matches PR4 byte-for-byte. The beta policy and profile/help/navigation links preserve PR4's purposes and add later Calendar, closure/retention, age/banner, Pinterest and analytics disclosures. Do not replace them with the older PR4 notice. Current `main` has no `/privacy` source. The beta notice's “historical subscription” wording predates the reinstated monthly Lab subscription, and its payment collection wording mentions hosted checkout but not the native SDK. Reconcile these disclosures and the official Updates/Rewards flows before public activation; this review is not legal approval.
